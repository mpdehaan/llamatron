# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A tracker-style text UI, with a Python framework underneath it, for producing MIDI clips for use in Ableton Live. It's at an early stage. The third-party dependencies are `mido`, `PyYAML` and `textual`, pinned in `requirements.txt`, which `setup.py` also reads. The package is `llamatron`, in `src/llamatron`, and the code and its tests import it by that name, so it has to be installed (as below) before anything runs.

## Commands

Set up the virtual environment once. This also installs the `llamatron` command, which `setup.py` points at `llamatron.cli:main`, and `-e` makes it use the code here rather than a copy:

```
python3 -m venv .venv
.venv/bin/python -m pip install -e .
```

Tests use the standard library's `unittest`. Run these from the repository root, after the install above:

```
.venv/bin/python -m unittest discover -s test                # all tests
.venv/bin/python -m unittest discover -s test -k test_name   # tests matching a name
```

Don't add `__init__.py` to `test/`, because a package with that name would clash with Python's standard library `test` package.

## Code

Source code is in `src/llamatron`, and tests are in a `test` folder at the top.

`Note` (`src/llamatron/note.py`) is immutable and built from a name, an octave and a required length. Lengths are fractions of a whole note, so `0.25` is a quarter note and `0.5` is a half note. `Rest(length)` is the same but silent. Notes compare and hash by MIDI number and length rather than spelling, so `Note('C#', 4, 0.25) == Note('Db', 4, 0.25)` and `Note('B#', 3, 0.25) == Note('C', 4, 0.25)`, while `name` keeps the spelling it was given.

Octave numbers start at `C0`, which is MIDI note 0, so the highest note is `G10` (127). This deliberately doesn't match Ableton's labels, where MIDI note 0 is `C-2`. Notes outside the MIDI range can't be constructed, and that includes `Cb0` and `G#10` and above. Double sharps and double flats aren't supported.

The octave is stored as `octave_number`. `half_step(n)` returns a new note of the same length, spelled with flats if the note's name has a flat and with sharps otherwise.

`Chord` (`src/llamatron/chord.py`) is an immutable group of notes, and chords compare by their sorted MIDI numbers and lengths. A chord's `length` is its longest note's, and that's how long it occupies in a clip. `ChordType` values are half steps above the root. `Note.to_chord(typ)` builds a chord upward from the note using `half_step`, so every note gets the root's length and chord tones follow its sharp or flat rule rather than proper chord spelling: C minor contains `D#`, not `Eb`. `src/llamatron/chord.py` imports `Note`, so `to_chord` imports from `llamatron.chord` inside the method to avoid a circular import.

`Scale` (`src/llamatron/scale.py`) is an immutable root note and `ScaleType`, and `Degree.to_note` reads notes from it. `ScaleType` values are one octave of half steps including the root (`0`). Scale types with identical values are Python enum aliases, so `ScaleType.AEOLIAN is ScaleType.MINOR` and `list(ScaleType)` includes only the first name.

`Song` (`src/llamatron/song.py`) stores a grid of `Clip` objects, one cell per `(Scene, Track)`, in a dict nested as `{scene id: {track id: clip}}`. The ids exist because names don't have to be unique, and other types don't need them. Tracks and scenes get theirs from `add_track` and `add_scene`: each song counts tracks and scenes separately from 0 in the order they're added, and the id is `None` before that. This means a track or scene can only join one song. Clips get a unique id when created. `Track`, `Scene` and `Clip` compare by identity, and grid methods reject scenes and tracks that aren't in the song.

`tempo_at(scene)` resolves as scene, then song, and `scale_at(scene, track)` resolves as clip, then scene, then song, both reading the current values each time. Clips deliberately have no tempo, because Live has no per-clip tempo for MIDI clips. Only `Song` has a default tempo (120, minimum 10), and a scene tempo of `None` means it uses the song's. A song's `scale` can be `None`, so `scale_at` can return `None`. Scales will be used by generator objects that haven't been designed yet.

`Clip.notes` is a list where each position is a `Note`, `Chord`, `Rest` or `Degree`, played in order. The setter also accepts shorthand and converts it to objects: `'E4'` is a `Note`, `3` is a `Degree`, and each dash is a quarter note of rest, whatever the `note_length`.

Binding is as late as possible, and the user wants new features to keep it that way. A `Degree` (`src/llamatron/note.py`, numbered from 1) stays a degree until `ClipTree` converts it with `song.scale_at(scene, track)`, so a clip follows its scene's or song's scale. A `Note` or `Degree` with a length of `None` takes `Clip.note_length`, which `clip.resolved_notes()` fills in without changing the clip. Missing scales and lengths raise `ValueError` at render, before any file is written. Generators keep degrees as degrees. Chords hold only `Note`s so far. `Clip.trim(n)` keeps the first `n` positions in place and returns the clip. `Clip.length` uses the same whole-note units, and `None` ends the clip after its last position, while any other value adds silence or cuts notes off to fit. There's deliberately no concept of time signature, because note timing only needs lengths and tempo. Tempo is in quarter notes per minute.

Fields on `Song`, `Track`, `Scene` and `Clip` are editable unless the user says otherwise, and the `_Validated` descriptor checks every assignment. The exception is `id`, which is read-only. `Note`, `Chord` and `Scale` remain immutable.

Renderers live in `src/llamatron/renderers`, and their tests go directly in `test/`, because discovery doesn't reach subfolders of `test/` without `__init__.py` files. `ClipTree` (`src/llamatron/renderers/clip_tree.py`) takes a directory and a `Song`, and `render()` writes `<scene_id>-<track_id>-<clip_name>.mid` for each filled slot (just `<scene_id>-<track_id>.mid` if the clip has no name, with ids zero-padded to three digits, and with whitespace and slashes in the name replaced by underscores), with the file name (minus `.mid`) as the MIDI track name, a tempo, and the clip's notes at each note's velocity. It must never delete existing files in the directory. Other files get a printed warning, while a file with a name it needs to write makes it print a warning and stop without writing anything.

`AbletonProject(directory, song, template)` (`src/llamatron/renderers/ableton_project.py`) takes the same inputs and writes a Live 12 set to `<directory>/<directory name>.als`, with clips in Session View and the scenes laid end to end in Arrangement View. A `.als` file is gzipped XML with no public documentation, so it edits a template Live saved, `src/llamatron/templates/live12.als`, installed with the package, whose first MIDI track must keep a clip because all the clip details are copied from it. Ids on tags ending in `Target`, `Targets.N` or `Pointee` must be unique across the set and below `NextPointeeId`. Tempo must be set on both the control and its automation. To check the format, read Live's own sets in `Contents/App-Resources/Core Library/Templates` and its schema in `Contents/App-Resources/Schema`. Tests can check structure, but only opening a set in Live proves it loads. Both renderers get note timing from `src/llamatron/renderers/timing.py`. `test/test_matrix.py` is an end-to-end example of the classes underneath the tracker.

Generators live in `src/llamatron/generators`, with the same test layout as renderers: `arp` and `auto_ratchet`, the two that a chain can use, `blend`, which morphing uses, and `base`. A generator's list of values must only step through notes and chords, so rests never use up a value (`test/test_generator_list_steps.py` checks this, so add new list generators there). Each subclasses `ClipGenerator` (`base.py`) and implements `_generate(clip)`, returning new notes and a length. `generate(clip)` then returns a new `Clip` with the same name and scale, leaving the original unchanged, so generators can be chained. `Arp(step, order, seed)` plays each chord one note at a time for the chord's full length, and leaves notes and rests alone. It restarts from the beginning until it fills a set `length`, and a `ChordOrder` of `UP` or `DOWN` goes by pitch rather than the order the chord was built in. `AutoRatchet(counts)` chops each note or chord into that many adjacent equal repeats, using the next count in a cycle, and rests don't use one up.



`Clip.section(start, end)` and `Clip.repeated(times)` cut and repeat clips by time. `Blend(target, amount, mode)` moves a clip towards an equally long target, with `BlendMode.LEFT`, `RIGHT` and `MIDDLE` sweeping the target in from one side or the center.


`src/llamatron/song_file.py` reads the YAML song format and builds a `Song`, and `src/llamatron/cli.py` is its command line, installed as `llamatron`. Without `--to` it opens the tracker, on a song if one is named, and with `--to` it renders instead. `--out`, `--template` and `--replace` are refused without `--to`. There's deliberately no separate command for the tracker, and `python -m llamatron` is the same as the command. `src/llamatron/song_writer.py` writes the same format. The format is mainly for machines now, but it stays readable for version control diffs where it can. `GENERATORS` in `src/llamatron/song_file.py` lists each generator's file settings, so new generators need adding there and using in an `examples/` song, which a test enforces. The format's rules are deliberate:

- A pattern holds `steps` and one list per row, mirroring the pattern editor: `degree`, `duration`, `accidental`, `octave`, `chord`, `velocity`, `probability`, `glide`, `ratchet`, `ratchet_offset`, `note_add`, `velocity_add` and `grab`. Rows of all blanks are left out. Nothing is packed into one value, so there's nothing to parse apart, except that durations stay as fractions like `3/16`, because decimals can't hold 1/3.
- Each step has its own duration, so steps aren't fixed slices of time and nothing draws bars. A blank degree is a rest, and a blank duration is the song's default, so no step can take no time, and a pattern needs at least one step. `drum: true` puts note letters in `degree`, and has no chords.
- Octaves are absolute, with no track offset, and are numbered as Live displays them, so `3` with degree 1 of C major is MIDI 60. The rest of this project numbers notes two octaves higher, and `LIVE_OCTAVE_OFFSET` converts. A degree past the top of the scale wraps up an octave, for a scene with a smaller scale.
- Chord symbols `M`, `m`, `M7`, `m7`, `dim` and `sus4` have a fixed sound, while `3` and `7` are built from the scale, so they follow scale changes.
- Probability is rolled at render from the song's `seed`, once per repeat and ratchet slice, so that a render plays the same every time. It deliberately doesn't use Live's per-note probability. `ratchet` splits a step into equal notes in the same time. `glide` runs a note slightly into the next one, which a synth with glide turned on slides across, and it does nothing before a rest or the same pitch.
- A scene launches clips and has no length of its own: it lasts as long as its longest clip that doesn't loop. A clip plays its pattern `repeat` times and stops. `loop: true` repeats it until that longest clip ends, and every clip in a scene looping is an error at build. A clip with a repeat above 1 can `morph_to` a second pattern in a `morph_style` across its repeats, and the second pattern is looped or cut to match the first. There's no way to morph across a scene's repeats.
- A clip's `rhythm_from` and `notes_from` each name another pattern, combining them before anything renders. They match step by step, not by time. Rhythm owns Duration, whether a step is a rest, Velocity, Probability, Ratchet and Glide, and it decides the clip's length. Notes own Degree, Accidental, Octave and Chord. Each step of the rhythm that isn't a rest plays the next note, rests in the notes are skipped, and the notes carry on across repeats and loops, so lists of different lengths drift apart on purpose. A morph's target plays as it's written.
- `ratchet_offset` moves each ratchet slice further along the scale, or by half steps in a drum pattern. `note_add` and `velocity_add` are the Cirklon's accumulators: each adds to a running total that starts at zero with each clip, applies from that step on, carries across repeats, and clears when it passes the pattern's `accumulator_limit` (default 36, either way). `note_add` moves along the scale and belongs to the notes side, and `velocity_add` belongs to the rhythm side. A note the totals push outside the MIDI range goes to the nearest octave that fits, while velocity stays from 1 to 127.
- `direction` on a pattern sets the order its steps play in: `forward`, `reverse_a`, `reverse_b`, `alternate`, `pendulum`, `random`, `brownian` or `eitherway`, as the Cirklon names them. `direction` on a clip overrides its patterns, including its rhythm, notes and source patterns, but not a morph's target. Whichever order the steps play in, a pass lasts as long as the pattern does, with the last step cut to fit, so a direction can't change how long a clip or scene is. Positions carry on across repeats, and chosen directions use the song's seed with a separate generator, so they can't change what probability rolls.
- `source_pattern` on a pattern gives its `grab` row somewhere to take notes from, like the Cirklon's note grab. The source moves on every step, grabbing or not, and a marked step that isn't a rest plays the source's Degree, Accidental, Octave and Chord at that moment, unless the source has a rest there. It reads patterns rather than what another track is playing.
- `scales` holds named scales, like `main: { root: F, type: minor }`, and new songs have `C Major`. A name can be anything, so that what `main` is can be decided later. `scale` on the song and on scenes must be one of these names. Scales resolve as scene and then song, and cells and patterns can't set one. The song can have no scale, and degrees then raise an error at build that names the problem.
- Every generator setting is named, YAML stays flat with `{}` only one level deep, cells always use the hash form inside a scene's `tracks`, and `tracks` is a plain list. `arps` names arpeggiators and `auto_ratchets` names AutoRatchets, each with their settings, and a chain is a list of steps like `arp: name` or `auto_ratchet: name`, with no settings of its own. A clip's `morph_style` is `left`, `right` or `middle`. A scene's `tempo_start` and `tempo_end` ramp the tempo across its `repeat`.

`src/llamatron/tui` is the text UI, which is meant to become the only way people use the program, and `llamatron [song]` or `./run_tui.sh [song]` opens it. It uses Textual with `ansi_color=True`, and draws with only bold, dim, reverse video and box characters, because terminal backgrounds differ. There are no tooltips, and it never saves or renders unless asked. `src/llamatron/tui/document.py` holds the song as plain file data, with everything that changes or reads it and no drawing, and it keeps references correct, so renames update everything. Each screen lists its keys once in `keys()`, which both handles and draws them, so no key can work without being shown, and a test checks this. `H` shows a page's `HELP` in a dialog on every page, which has to fit an 80 by 24 console, and a test checks that too. Upper and lower case are the same key, Tab goes back and never quits, and Q quits only from the main screen. Every list a page can add to has a `+` row at the bottom, where Enter does the same as pressing `+`. On settings pages, left and right do the same as `-` and `+`. Deleting anything still used is refused with up to five uses listed, and otherwise confirms. Don't name a screen's method after one Textual has, such as `render` or `remove`, because that breaks screens in ways that only show when they close, and a test checks this too. In the pattern editor, typing never moves the cursor or grows the grid, and digits build up a number in a cell until the cursor moves or a number would be out of range. `A` switches the rows under Degree between normal and advanced, because all of them can't fit an 80 by 24 console. `F` reverses the steps after the cursor, `S` swaps both sides of it, and the cursor stays on its step so that pressing either again undoes it. `L` loads a copy of another pattern over this one. On a drum pattern's Note row, `A` and `F` are note letters instead. `test/test_tui_pages.py` presses real keys, and is what makes the test suite take over a minute. New pattern generators are planned for `src/llamatron/generators` and mutators for `src/llamatron/pattern_mutators`, working on patterns rather than clips.

`backup/` holds code the tracker doesn't use, in the same layout as the project, so that anything can be moved straight back: the demos, the older generators, the analyzers, importers and `Score`, and their tests. Nothing imports it, its tests don't run, and its code would need moving back to work. `test/test_tracker_midi.py` checks the whole path from a song to MIDI using Mary Had a Little Lamb, and deliberately checks only that the notes and an accompaniment come out, not exact timing, so that the math stays free to improve.
