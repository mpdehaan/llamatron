# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Python domain specific language and framework for producing MIDI clips for use in Ableton Live. It's at an early stage, with no packaging config yet. The third-party dependencies are `mido`, `PyYAML` and `textual`, pinned in `requirements.txt`.

## Commands

Set up the virtual environment once:

```
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Tests use the standard library's `unittest`. Run these from the repository root so that `src` can be imported:

```
.venv/bin/python -m unittest discover -s test                # all tests
.venv/bin/python -m unittest discover -s test -k test_name   # tests matching a name
```

Don't add `__init__.py` to `test/`, because a package with that name would clash with Python's standard library `test` package.

## Code

Source code is in `src`, and tests are in a parallel `test` folder.

`Note` (`src/note.py`) is immutable and built from a name, an octave and a required length. Lengths are fractions of a whole note, so `0.25` is a quarter note and `0.5` is a half note. `Rest(length)` is the same but silent. Notes compare and hash by MIDI number and length rather than spelling, so `Note('C#', 4, 0.25) == Note('Db', 4, 0.25)` and `Note('B#', 3, 0.25) == Note('C', 4, 0.25)`, while `name` keeps the spelling it was given.

Octave numbers start at `C0`, which is MIDI note 0, so the highest note is `G10` (127). This deliberately doesn't match Ableton's labels, where MIDI note 0 is `C-2`. Notes outside the MIDI range can't be constructed, and that includes `Cb0` and `G#10` and above. Double sharps and double flats aren't supported.

The octave is stored as `octave_number` because `octave(n)` is a method. `half_step(n)`, `whole_step(n)` and `octave(n)` return new notes of the same length. `half_step` and `whole_step` respell the result with flats if the note's name has a flat and with sharps otherwise, while `octave` keeps the spelling.

`Chord` (`src/chord.py`) is an immutable group of notes, and chords compare by their sorted MIDI numbers and lengths. A chord's `length` is its longest note's, and that's how long it occupies in a clip. `ChordType` values are half steps above the root. `Note.to_chord(typ)` builds a chord upward from the note using `half_step`, so every note gets the root's length and chord tones follow its sharp or flat rule rather than proper chord spelling: C minor contains `D#`, not `Eb`. `src/chord.py` imports `Note`, so `to_chord` imports from `src.chord` inside the method to avoid a circular import.

`Scale` (`src/scale.py`) is an immutable root note and `ScaleType`. Iterating it yields notes lazily from the root up to the top of the MIDI range, across every octave, and `notes()` returns the same notes as a list. `count(n)` returns the first `n` notes, and `octaves(n)` returns the notes up to and including the root `n` octaves higher. Both raise `ValueError` rather than return a short list. Every note takes the root's length. It never yields notes below the root, and its spelling follows the same `half_step` rule as chords. `ScaleType` values are one octave of half steps including the root (`0`). Scale types with identical values are Python enum aliases, so `ScaleType.AEOLIAN is ScaleType.MINOR` and `list(ScaleType)` includes only the first name.

`Song` (`src/song.py`) stores a grid of `Clip` objects, one cell per `(Scene, Track)`, in a dict nested as `{scene id: {track id: clip}}`. The ids exist because names don't have to be unique, and other types don't need them. Tracks and scenes get theirs from `add_track` and `add_scene`: each song counts tracks and scenes separately from 0 in the order they're added, and the id is `None` before that. This means a track or scene can only join one song. Clips get a unique id when created. `Track`, `Scene` and `Clip` compare by identity, and grid methods reject scenes and tracks that aren't in the song.

`remove_track` and `remove_scene` also remove their clips and set the object's id back to `None`. Ids aren't reused, so gaps in the numbering are expected.

`tempo_at(scene)` resolves as scene, then song, and `scale_at(scene, track)` resolves as clip, then scene, then song, both reading the current values each time. Clips deliberately have no tempo, because Live has no per-clip tempo for MIDI clips. Only `Song` has a default tempo (120, minimum 10), and a scene tempo of `None` means it uses the song's. A song's `scale` can be `None`, so `scale_at` can return `None`. Scales will be used by generator objects that haven't been designed yet.

`Clip.notes` is a list where each position is a `Note`, `Chord`, `Rest` or `Degree`, played in order. The setter also accepts shorthand and converts it to objects: `'E4'` is a `Note`, `3` is a `Degree`, and each dash is a quarter note of rest, whatever the `note_length`.

Binding is as late as possible, and the user wants new features to keep it that way. A `Degree` (`src/note.py`, numbered from 1) stays a degree until `ClipTree` converts it with `song.scale_at(scene, track)`, so a clip follows its scene's or song's scale. A `Note` or `Degree` with a length of `None` takes `Clip.note_length`, which `clip.resolved_notes()` fills in without changing the clip. Missing scales and lengths raise `ValueError` at render, before any file is written. Generators keep degrees as degrees, and `Transpose` records moves on them with `Degree.moved`, so it needs no scale for them. Chords hold only `Note`s so far. `Clip.trim(n)` keeps the first `n` positions in place and returns the clip. `Clip.length` uses the same whole-note units, and `None` ends the clip after its last position, while any other value adds silence or cuts notes off to fit. There's deliberately no concept of time signature, because note timing only needs lengths and tempo. Tempo is in quarter notes per minute.

Fields on `Song`, `Track`, `Scene` and `Clip` are editable unless the user says otherwise, and the `_Validated` descriptor checks every assignment. The exception is `id`, which is read-only. `Note`, `Chord` and `Scale` remain immutable.

Renderers live in `src/renderers`, and their tests go directly in `test/`, because discovery doesn't reach subfolders of `test/` without `__init__.py` files. `ClipTree` (`src/renderers/clip_tree.py`) takes a directory and a `Song`, and `render()` writes `<scene_id>-<track_id>-<clip_name>.mid` for each filled slot (just `<scene_id>-<track_id>.mid` if the clip has no name, with ids zero-padded to three digits, and with whitespace and slashes in the name replaced by underscores), with the file name (minus `.mid`) as the MIDI track name, a tempo, and the clip's notes at each note's velocity. It must never delete existing files in the directory. Other files get a printed warning, while a file with a name it needs to write makes it print a warning and stop without writing anything.

`AbletonProject(directory, song, template)` (`src/renderers/ableton_project.py`) takes the same inputs and writes a Live 12 set to `<directory>/<directory name>.als`, with clips in Session View and the scenes laid end to end in Arrangement View. A `.als` file is gzipped XML with no public documentation, so it edits a template Live saved, `ableton/live12 Project/live12.als`, whose first MIDI track must keep a clip because all the clip details are copied from it. Ids on tags ending in `Target`, `Targets.N` or `Pointee` must be unique across the set and below `NextPointeeId`. Tempo must be set on both the control and its automation. To check the format, read Live's own sets in `Contents/App-Resources/Core Library/Templates` and its schema in `Contents/App-Resources/Schema`. Tests can check structure, but only opening a set in Live proves it loads. Both renderers get note timing from `src/renderers/timing.py`. `test/test_matrix.py` is an end-to-end example that the user reads to judge the API, so keep it readable.

Generators live in `src/generators`, with the same test layout as renderers. Only `arp`, `auto_ratchet`, `blend` (which morphing uses) and what those need are still there. All the others are in `src/legacy/generators`, where the user has parked them to delete later: song files and demos still import them from there, and the text UI shows them read-only. A generator's list of probabilities or multipliers must only step through notes and chords, so rests never use up a value (`test/test_generator_list_steps.py` checks this, so add new list generators there). Each subclasses `ClipGenerator` (`base.py`) and implements `_generate(clip)`, returning new notes and a length. `generate(clip)` then returns a new `Clip` with the same name and scale, leaving the original unchanged, so generators can be chained. `Repeater(times)` plays each position `times` times in the time it originally took, so `Repeater(2)` turns a whole note into two half notes and the clip keeps its total duration and `length`. `Arp(step, order, seed)` plays each chord one note at a time for the chord's full length, and leaves notes and rests alone. It restarts from the beginning until it fills a set `length`, and a `ChordOrder` of `UP` or `DOWN` goes by pitch rather than the order the chord was built in. `MixUp(probabilities, seed)` steps through the notes swapping each with a randomly chosen other note, `MixUp2(probabilities, seed)` swaps each with the next note, and both leave rests in place, `Reverse()` reverses the positions (and any silence up to a set `length`), and `Transpose` takes exactly one of `half_steps`, `whole_steps`, `octaves` or `scale_notes`, where positive moves up and negative moves down. Generators only see the clip, so `Transpose(scale_notes=...)` uses its own `scale` argument or else `clip.scale`, and scene or song scales have to be passed in with `song.scale_at(scene, track)`.

`TransposeScale(input_scale, output_scale)` moves notes to the same degree in another scale. It turns notes into degrees with `Scale.degree_of` and sets the new clip's scale to the output scale. A generator changes the new clip's scale by overriding `_new_scale`. `DurationChange(factors)` multiplies each note's or chord's length by the next factor in a cycle, and rests don't use one up. Every note keeps its start time: shorter notes get a new rest after them, and longer ones play through following rests but stop at the next note or the end of the clip, so notes never overlap. `AutoRatchet(counts)` chops each note or chord into that many adjacent equal repeats, using the next count in a cycle, and rests don't use one up. `Backfill(probabilities, scale, seed)` may add a note halfway between each pair of neighboring notes, using the next probability per gap. The new note is the scale note strictly between the two pitches that's closest to their midpoint, with ties going lower, and it lasts as long as the first note. It adds nothing if no such note exists or the new note wouldn't fit in the silence, and it never fills the gap after the last note. Between two degrees in one octave it picks the middle degree, which needs no scale. `Accompany(scale, measure_length, octave)` returns a clip of chords for a melody, picking for each measure the three-note scale chord whose notes sound longest. `demo/mary_jazz.py` is the showcase, so it should use every generator (a test checks this) and stay short.

Importers live in `src/importers`. `ClipTreeImporter(directory).load()` (`src/importers/clip_tree.py`) reads `ClipTree` output back into a new `Song`, placing clips by their file names and putting each file's tempo on its scene. Ids are renumbered from 0, spellings come back as sharps, only clip names survive, and overlapping notes that don't start together raise `ValueError`.

`Clip.section(start, end)`, `Clip.measures(first, last, measure_length)`, `Clip.repeated(times)` and `join_clips(clips)` cut and join clips by time. `Stretch(factor)` scales all lengths. `Hold(length, every)` makes every Nth note slightly longer, and `Delay(amount, every)` plays it slightly late. `Blend(target, amount, slice_length, points, seed, mode, strong_beat, scale)` moves a clip towards an equally long target. `BlendMode.LEFT`, `RIGHT` and `MIDDLE` sweep the target in from one side or the center, `SLICES` plays slices of either, `STRONG_BEATS` gives strong beats the target's pitch, and `CONTOUR` moves every note part way along the scale. Slices and strong beats have fixed thresholds from the seed, so raising the amount only ever adds changes. Keep the seed the same across a morph, and for its melody and chords. `Harmonize(charts, scale)` plays the first chart's chord in each slot that doesn't clash with the melody, then the best-fitting scale chord that doesn't. Chord charts are ordinary clips of chords, so generators work on them too. `TakeRhythm(rhythm)` plays a clip's pitches in another clip's rhythm, `ForceScale(scale)` moves notes outside a scale to the closest one inside it, and `Smoother(chords, max_leap)` moves clashing notes to chord notes and big leaps by an octave. In `BlendPiece`, whichever tune is ahead in a blend (the first at 50 or below) sets the scale, rhythm and chords. A demo's `PROGRESSION` only ever rises towards Rising Sun, and chords arpeggiate faster as Rising Sun's slower melody takes over. `Counterpoint(chords, style, low, high, step, delay, scale, seed)` writes a line below a melody as `NOTE_AGAINST_NOTE`, `FLOWING` or `CANON`, searching for the line that best follows its rules. Rules it must follow are checked in `test/test_counterpoint.py`. `Register(low, high)` moves notes by octaves into a range. `demo/blend_base.py` holds the shared `BlendPiece` recipe, which gives bass, chords and melody separate registers, with a piano in mind, and adds `kick` and `snare` tracks. `demo/gifts_to_sun.py` uses it. A second pair of tunes (Nobody Knows and Saints) was tried and then removed, after exposing bugs in `ScaleDetector`, `ClashFinder` and `Smoother`. Fix problems like these in `src/`, not in the demos or tests.

`src/analyzers` holds tools that look at clips without changing them, and they're there to be deleted if they don't help the sound. `PhraseFinder` and `ChordChangeFinder` return times to slice at, `ClashFinder` reports melody notes on or lasting a beat that sit a half step from a chord note, and `ScaleDetector` guesses a clip's scale. `src/score.py` has `Score`, which adds melody and chord scenes in order, and `ramp`. `demo/tunes.py` has the public domain tunes, and must not include copyrighted melodies or arrangements such as The Animals' version of Rising Sun.

`src/song_file.py` reads the YAML song format and builds a `Song`, and `src/cli.py` is its command line. `src/song_writer.py` writes the same format. The format is mainly for machines now, but it stays readable for version control diffs where it can. `GENERATORS` in `src/song_file.py` lists each generator's file settings, so new generators need adding there and using in an `examples/` song, which a test enforces for everything outside `src/legacy`. The format's rules are deliberate:

- A pattern holds `steps` and one list per row, mirroring the pattern editor: `degree`, `duration`, `accidental`, `octave`, `chord`, `velocity`, `probability`, `glide`, `ratchet`, `ratchet_offset`, `note_add`, `velocity_add` and `grab`. Rows of all blanks are left out. Nothing is packed into one value, so there's nothing to parse apart, except that durations stay as fractions like `3/16`, because decimals can't hold 1/3.
- Each step has its own duration, so steps aren't fixed slices of time and nothing draws bars. A blank degree is a rest, and a blank duration is the song's default, so no step can take no time, and a pattern needs at least one step. `drum: true` puts note letters in `degree`, and has no chords.
- Octaves are absolute, with no track offset, and are numbered as Live displays them, so `3` with degree 1 of C major is MIDI 60. The rest of this project numbers notes two octaves higher, and `LIVE_OCTAVE_OFFSET` converts. A degree past the top of the scale wraps up an octave, for a scene with a smaller scale.
- Chord symbols `M`, `m`, `M7`, `m7`, `dim` and `sus4` have a fixed sound, while `3` and `7` are built from the scale, so they follow scale changes.
- Probability is rolled at render from the song's `seed`, once per repeat and ratchet slice, so that a render plays the same every time. It deliberately doesn't use Live's per-note probability. `ratchet` splits a step into equal notes in the same time. `glide` runs a note slightly into the next one, which a synth with glide turned on slides across, and it does nothing before a rest or the same pitch.
- A scene launches clips and has no length of its own: it lasts as long as its longest clip that doesn't loop. A clip plays its pattern `repeat` times and stops. `loop: true` repeats it until that longest clip ends, and every clip in a scene looping is an error at build. A clip with a repeat above 1 can `morph_to` a second pattern in a `morph_style` across its repeats, and the second pattern is looped or cut to match the first.
- A clip's `rhythm_from` and `notes_from` each name another pattern, combining them before anything renders. They match step by step, not by time. Rhythm owns Duration, whether a step is a rest, Velocity, Probability, Ratchet and Glide, and it decides the clip's length. Notes own Degree, Accidental, Octave and Chord. Each step of the rhythm that isn't a rest plays the next note, rests in the notes are skipped, and the notes carry on across repeats and loops, so lists of different lengths drift apart on purpose. A morph's target plays as it's written.
- `ratchet_offset` moves each ratchet slice further along the scale, or by half steps in a drum pattern. `note_add` and `velocity_add` are the Cirklon's accumulators: each adds to a running total that starts at zero with each clip, applies from that step on, carries across repeats, and clears when it passes the pattern's `accumulator_limit` (default 36, either way). `note_add` moves along the scale and belongs to the notes side, and `velocity_add` belongs to the rhythm side. A note the totals push outside the MIDI range goes to the nearest octave that fits, while velocity stays from 1 to 127.
- `direction` on a pattern sets the order its steps play in: `forward`, `reverse_a`, `reverse_b`, `alternate`, `pendulum`, `random`, `brownian` or `eitherway`, as the Cirklon names them. `direction` on a clip overrides its patterns, including its rhythm, notes and source patterns, but not a morph's target. Whichever order the steps play in, a pass lasts as long as the pattern does, with the last step cut to fit, so a direction can't change how long a clip or scene is. Positions carry on across repeats, and chosen directions use the song's seed with a separate generator, so they can't change what probability rolls.
- `source_pattern` on a pattern gives its `grab` row somewhere to take notes from, like the Cirklon's note grab. The source moves on every step, grabbing or not, and a marked step that isn't a rest plays the source's Degree, Accidental, Octave and Chord at that moment, unless the source has a rest there. It reads patterns rather than what another track is playing. A generator reading a pattern ignores direction and grab, and reads it as written.
- `scales` holds named scales, like `main: { root: F, type: minor }`, and new songs have `C Major`. A name can be anything, so that what `main` is can be decided later. `scale` on the song and on scenes must be one of these names. Scales resolve as scene and then song, and cells and patterns can't set one. The song can have no scale, and degrees then raise an error at build that names the problem. A generator's scale setting can be a name, or text like `F minor`.
- Every generator setting is named, YAML stays flat with `{}` only one level deep, cells always use the hash form inside a scene's `tracks`, and `tracks` is a plain list. Chains on a cell apply first. A setting becomes a gradient with `name_start` and `name_end`, across a scene's `repeat`. `blend` takes `to` and `style`, and always runs from 0 to 100. `arps` names arpeggiators and `auto_ratchets` names AutoRatchets, each with their settings, and a chain step `arp: name` or `auto_ratchet: name` uses one. Pattern settings are looped or cut to the clip's length at that step, so they still fit after `stretch`.
- `paint` is legacy, and the user intends to remove it. It lists `tracks` and written-out `scenes`, counting from 1, applies after a cell's chains, and gradients count through its scenes. The examples still use it. The text UI never mentions paint, and drops it quietly when its track or chain is deleted. Clips and generator settings that read another track have been removed, so nothing has to be built in any order. 

`src/tui` is the text UI, which is meant to become the only way people use the program, and `./run_tui.sh` or `python -m src.tui [song]` opens it. It uses Textual with `ansi_color=True`, and draws with only bold, dim, reverse video and box characters, because terminal backgrounds differ. There are no tooltips, and it never saves or renders unless asked. `src/tui/document.py` holds the song as plain file data, with everything that changes or reads it and no drawing, and it keeps references correct: renames update everything, and paint's scene numbers follow scenes that move. Each screen lists its keys once in `keys()`, which both handles and draws them, so no key can work without being shown, and a test checks this. `H` shows a page's `HELP` in a dialog on every page, which has to fit an 80 by 24 console, and a test checks that too. Upper and lower case are the same key, Tab goes back and never quits, and Q quits only from the main screen. Every list a page can add to has a `+` row at the bottom, where Enter does the same as pressing `+`. On settings pages, left and right do the same as `-` and `+`. Deleting anything still used is refused with up to five uses listed, and otherwise confirms. Don't name a screen's method after one Textual has, such as `render` or `remove`, because that breaks screens in ways that only show when they close, and a test checks this too. In the pattern editor, typing never moves the cursor or grows the grid, and digits build up a number in a cell until the cursor moves or a number would be out of range. `A` switches the rows under Degree between normal and advanced, because all of them can't fit an 80 by 24 console. `F` reverses the steps after the cursor, `S` swaps both sides of it, and the cursor stays on its step so that pressing either again undoes it. `L` loads a copy of another pattern over this one. On a drum pattern's Note row, `A` and `F` are note letters instead. `test/test_tui_pages.py` presses real keys, and is what makes the test suite take over a minute. New pattern generators are planned for `src/generators` and mutators for `src/pattern_mutators`, working on patterns rather than clips.

`demo/` holds simple examples that show people how to use the program, so they should stay short and easy to read. They write to `./output/<name>`, which is ignored by Git, while tests use temporary directories because a second run into the same folder would stop at the existing files. Run them from the repository root as modules, such as `.venv/bin/python -m demo.mary`, because `python demo/mary.py` can't import `src`.
