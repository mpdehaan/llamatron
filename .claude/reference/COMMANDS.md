# Commands

Reference notes for Claude: every script of `user_scripts/` and `internal_tools/` and every tool worth running again, with what
each is for. It isn't imported: read it when a script or a tool is needed, and update it in the same change when a script is
added, renamed or changed. `CLAUDE.md` keeps only the commands every session needs.

The everyday commands are short scripts, each named after what it does with underscores and saying so in its `# What it does:` line, in two folders by who runs them (the user's layout, which replaced the Makefile), and the top folder holds only `setup.sh` (the environment and the dependencies, then the backend through `internal_tools/build_backend.sh`), `build.sh` (llamatron2 and the backend Set up the virtual environment once. This also installs the `llamatron` command, which `pyproject.toml` points at `llamatron.cli:main`, and `-e` makes it use the code here rather than a copy:

```
python3 -m venv .venv
.venv/bin/python -m pip install -e .
```

`.claude/rules/TESTING.md` says how the tests are run and written. In short: `py_legacy/internal_tools/test.sh` runs the whole suite in parallel, in about two and a half minutes, and `py_legacy/internal_tools/test_changed.sh` only the classes that cover what changed, by the map `py_legacy/internal_tools/test_map.sh` makes with `coverage`. There is no git hook, by the user's rule, so Claude runs `internal_tools/check_before_commit.sh` (the tests that cover the change) before committing code, commits documents alone without a run, and `internal_tools/push_all.sh` raises the version once a push and runs the whole suite before every push.
